| 記録の削除・上書き防止 | 元DB・元テーブル保持、移行台帳で重複防止、変更検知時は全件ロールバック |
| 将来の変更への備え | バージョン付きマイグレーション。新しすぎるDBは起動を拒否 |

旧study_logsの自動取り込みは行わない。旧形式と現行形式に同じ学習が記録されている可能性があり、
自動判断で統合すると重複や誤対応が起きるため。移行コマンドは確認後に明示的に実行できる。
同じファイル内の元テーブルを取り込む場合も元の全列をそのまま残す。

バックアップと移行処理は合成データの一時DBで検証している。
サーバーのディスク永続性はホスティング設定に依存し、この変更だけで保証するものではない。

## 3.4 安全性

| 画像の確認項目 | 対応 |
| --- | --- |
| 本番debug無効 | Flask設定と直接起動の両方でFalse |
| 内部情報の非公開 | DB障害は503、内部処理の失敗は500。公開画面に例外文・パスを含めない |
| 入力値検証 | 型・日付・範囲・文字数・リクエストサイズ。SQLは値をプレースホルダーへ渡す |
| DB例外処理 | 接続を確実に閉じ、書き込み・移行は同一トランザクションで取り消す |
| CSRF | ロック解除を含む全POSTに既存のトークン照合を継続 |
| 秘密情報の環境変数管理 | PIN・署名鍵はサーバー設定。公開コード・記録に保存しない |
| 公開ファイルの点検 | .env、SQLite、バックアップを除外。追跡ファイルを点検 |

追加でCSP、nosniff、フレーム埋め込み拒否、no-storeを設定する。
分析ルールの学術的妥当性・学習効果を実証したという意味ではない。
