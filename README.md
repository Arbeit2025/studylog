# studylog

studylog は、Flask と SQLite で作られたシンプルな学習ログアプリです。
  
ブラウザから学習前の計画を保存し、学習後に同じログへ結果を追記できます。
一覧では前後の変化、表示範囲内の合計学習時間、平均集中度・平均理解度を確認できます。

小さくてシンプルな学習ログを目的としています。


Single-file Flask + SQLite study log app.

## Features
- 学習内容、カテゴリ、目標、予定時間、学習方法の保存
- 学習前の集中できそう度・理解度・自信度（1〜5）の保存
- 学習後の実際の時間・集中度・理解度・自信度、振り返りの保存
- 学習前後の確認テスト得点（0〜100点換算、任意入力）の保存
- 学習前だけの保存、途中保存、学習後の追記・編集・削除
- 理解度・自信度・確認テストの前後差、予定時間と実績の比較
- 期間・カテゴリでの絞り込みと、学習完了のログを対象にした時間・平均の集計
- 同じカテゴリの直前5件と、時間・集中度・理解度・自信度・確認テストの比較
- 状態の暫定分類、判定理由、比較データの充足度、4種類の支援の方向の表示

## 記録の流れ
サイトを開いたら、数字4桁の暗証番号でロックを解除します。解除後は同じ
ブラウザのセッション中、最長12時間利用できます。一覧・編集画面の「ロック」で
すぐに入り直せます。ブラウザがセッションを復元する場合もあるため、利用を
終えるときは「ロック」を使ってください。

1. 学習内容と学習前の計画・評価を入力し、「学習前を保存」を押します。
2. 一覧の「学習後を記録」を開き、実際の学習時間と学習後の結果を入力します。
3. 「学習後まで保存」を押すと、同じログが学習完了になります。

学習後に前後の情報をまとめて保存することもできます。実際の学習時間は
学習完了時に1分以上の整数が必須です。評価と確認テストは任意で、未入力は
未測定として保存します。前後両方が記録された項目だけ差分を表示します。
学習前の集中できそう度は予測値、学習後の集中度は振り返りの評価です。

## 状態分類と過去ログ比較
一覧の各ログで状態の候補と支援案を表示します。「比較の内訳」を開くと、
各項目の今回値、過去平均、差、比較件数、比較に使ったログを確認できます。

- 基準値は同じカテゴリの完了ログのうち、学習日が古い順・同日はID順で
  そのログより前にある直近5件の平均です。本人のDB内だけで計算し、別カテゴリ、
  学習中、対象ログ自身、後続ログは混ぜません。カテゴリ未設定は未設定同士で比較します。
- 表示期間の絞り込みとは独立して基準値を計算します。編集・削除・過去日付での
  追加は、次の表示時に後続ログの比較にも反映されます。
- 未測定・範囲外・不正な旧値は項目ごとに除外します。0点は有効です。
  過去5件の中に未測定値があっても、それより前のログで埋めません。
- 過去との差に `min(その項目の比較件数 / 5, 1)` を掛けて少数記録の影響を弱めます。
  過去傾向の判定はその項目が3件以上あり、補正後の差が±1段階以上のときです。
  表に出す差は補正前です。「比較データの充足度」は評価3項目の最少比較件数で示し、
  判定の正答確率や統計的信頼区間を意味しません。

試作ルール `state-v1` は次の順で最初に一致した状態を表示します。

| 優先順 | 状態候補 | 条件 | 支援の方向 |
| --- | --- | --- | --- |
| 1 | 自己評価のずれ | 自信度と確認テスト参考換算値との差が±1.5段階以上。テスト未記録なら理解度との差 | 自己認識の促進 |
| 2 | 理解の停滞 | 理解度が2以下、または補正後の過去差が−1以下 | 学習機会の提供 |
| 3 | 実行・集中の見直し | 集中度が2以下、または補正後の過去差が−1以下 | 個別のフィードバック・介入 |
| 4 | 自信の低下 | 自信度が2以下、または補正後の過去差が−1以下 | 自己認識の促進 |
| 5 | 前進傾向 | 学習後の3評価があり、理解度または集中度の補正後の差が＋1以上 | 学習状況の可視化 |
| 6 | 大きな変化なし／今回の評価は中程度以上（暫定） | 学習後の3評価が3以上で、上の条件に一致しない | 学習状況の可視化 |

学習中は判定待ち、評価不足でどの条件にも当てはまらない場合は判定保留です。
確認テストの参考換算は `1 + 得点 / 25` です。テストの内容や難易度の違いは
補正していません。閾値・換算式は今回定めた試作仕様で、検証済みの能力尺度ではありません。
学習時間は比較表示だけに使い、長短をそのまま良否や計画の達成度に置き換えません。

卒論由来の4分類は「支援の方向」です。状態分類そのものの4分割ではありません。
分析は読み取り時に再計算し、元の評価・メモを変更しません。分析結果の固定保存、
支援の採否・結果を学習した動的補正は今回の実装には含みません。

## データの保存
データはアプリと同じディレクトリの `studylog.db` に保存します。
起動時に `logs` テーブルへ不足する列を追加します。以前の記録は学習完了として
引き継ぎ、存在しない学習前の評価・得点・保存日時は補いません。
旧 `study_logs` テーブルや別DBからの自動移行は行いません。

学習状態は `status`（`in_progress` / `completed`）、前評価は
`before_concentration` / `before_understanding` / `before_confidence`、後評価は
既存の `concentration` / `understanding` / `confidence` に保存します。
得点は `before_test_score` / `after_test_score`、前後の初回保存日時は
`before_saved_at` / `after_saved_at`、最終更新日時は `updated_at` です。
新しい保存日時はUTCのISO 8601形式です。既存の日時はそのまま保持します。

## 暗証番号の設定
暗証番号は画面や公開ソースに埋め込まず、サーバーの環境変数で設定します。

| 環境変数 | 設定内容 |
| --- | --- |
| `STUDYLOG_PIN` | 半角数字4桁（先頭の0も可） |
| `STUDYLOG_SECRET_KEY` | セッション署名用のランダムな秘密鍵。32文字以上 |
| `STUDYLOG_COOKIE_SECURE` | 通常は未設定（HTTPS専用Cookie）。ローカルHTTPで試す場合だけ `0` |

Renderでは既存の `studylog1` サービスのEnvironmentへ設定します。環境変数を
保存した後、その設定を取り込むデプロイを実施してください。PINや秘密鍵を
README、テスト、`.env` 等へ書いてコミットしないでください。

PINまたは秘密鍵が未設定・不正ならHTTP 503で閉じ、ログの表示・変更を許可しません。
PIN・秘密鍵を変更すると、既存の解除済みセッションも無効になります。
ログの一覧・編集だけでなく、追加・更新・削除への直接アクセスもサーバー側で保護し、
すべてのPOSTフォームでCSRFトークンを確認します。

5回連続で入力を間違えると、30秒間は正しい番号でも解除できません。
最後の誤入力から5分空いた場合は、連続失敗数をリセットします。制限は
SQLiteの専用テーブル `studylog_auth_attempts` で共有するため、Cookieの削除や
プロセスの再起動では解除されません。1人用の簡易ロックなので、別の訪問者による
誤入力でも一時的に待機が発生します。再デプロイ後の制限の保持はDBの永続性に依存します。
4桁PINは簡易的なアクセス制限です。個別アカウント・多要素認証・データの暗号化は行いません。

## Run (local)
```bash
pip install -r requirements.txt
python - <<'PY'
import getpass
import os
import secrets
os.environ["STUDYLOG_PIN"] = getpass.getpass("暗証番号（数字4桁）: ")
os.environ["STUDYLOG_SECRET_KEY"] = secrets.token_hex(32)
os.environ["STUDYLOG_COOKIE_SECURE"] = "0"
from soapp import app
app.run(debug=False)
PY
```
この起動例では秘密鍵を起動時に生成するため、再起動すると入り直しになります。
継続したセッションが必要な運用では、十分にランダムな秘密鍵を環境変数で保持します。

## Tests
```bash
python -m unittest discover -s tests -v
python tests/http_auth_smoke.py
```
実アプリを一時ディレクトリへコピーし、FlaskのHTTPルートとSQLiteで検証します。
普段使っているDBは変更しません。追加・前後保存・繰り返し編集・再起動・
旧DBの列追加・入力エラー・集計・絞り込み・削除を確認します。
認証テストは専用の仮の番号とランダムな鍵を使います。未解除時の閲覧・変更拒否、
誤入力・形式不正、ロック解除・再ロック、回数制限・待機後の復帰、期限切れ、
Cookie属性・改ざん、CSRF、不正なサーバー設定も検証します。
